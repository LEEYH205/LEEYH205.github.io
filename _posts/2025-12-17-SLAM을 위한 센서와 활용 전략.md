# 자율주행에 사용되는 센서

• Proprioceptive Sensor

• Exteroceptive Sensor

• Interoceptive Sensor

## Proprioceptive Sensor

• 주변 환경의 상태와 관련없이 로봇 자기 자신의 state
값을 읽을 수 있는 센서

• 관절 각도, 회전 속도, 가속도, 토크 등을 읽어내어 로봇의
위치, 자세, 속도 등의 자기 상태 정보를 제공

• 예) Wheel Encoder, IMU

## Exteroceptive Sensor

• 주변 환경에 대한 상태를 읽는 센서

• 로봇이 주변 환경과 상호작용하고, 장애물이나 물체를
인식하며, 환경에 대한 정보를 수집하는 데 사용

• 예) Camera, LiDAR, Ultrasonic, Infrared Sensor, GNSS

## Interoceptive Sensor

• 로봇의 내부 상태, 특히 로봇의 생리적 및 기능적 상태를
모니터링하는 센서

• 로봇의 시스템 상태를 감지하여 안정적이고 효율적인 작동을
보장하며, 내부의 이상 상황을 사전에 감지

• 예) Temperature Sensor, Battery Monitoring Sensor,
Current Sensor

# Proprioceptive Sensor for SLAM

## Wheel Encoder

• 바퀴의 회전량 (RPM)을 측정하는 센서
- RPM * 바퀴 둘레 = 이동량
- brush, optical, magentic, inductive, capacitative... 만드는 방법은 여러가지임

• 장점
- 저렴한 가격
- 최신 모터에는 기본적으로 탑재

• 단점
- 3-DOF 모션만 추정 가능 (x, y, yaw)
- 주행에 따른 오차 누적
- 휠 슬립 (wheel slip), 바퀴의 변형


## IMU (Inertial Measurement Units)

• Linear accelerator (선형가속도 측정) 와 Angular gyroscope (각속도
측정)를 포함하는 센서
- pring-damper system의 원리를 이용하여 만든 시스템

• 장점
- 저렴한 consumer grade 제품 존재
- 높은 sensitivity와 샘플링 주기 (100Hz, 200Hz, 400Hz, 800Hz 등)

• 단점
- 시간이 지남에 따라 bias에 의한 drift가 생김
- 높은 정확도 + 낮은 drift를 가진 tactical grade IMU는 금액이 높음

### IMU - SLAM 관점에서 활용

• 센서퓨전1: Wheel Inertial Odometry
- 보통 EKF 기반으로 퓨전 ([robot_localization 패키지 wiki](https://docs.ros.org/en/noetic/api/robot_localization/html/index.html))

• 센서퓨전2: Visual Inertial Odometry & SLAM
- 예: [VINS-Mono](https://github.com/HKUST-Aerial-Robotics/VINS-Mono)

• 센서퓨전3: LiDAR Inertial Odometry & SLAM
- 예: [LIO-SAM](https://github.com/TixiaoShan/LIO-SAM)

## GNSS (Global Navigation Satellite System)

• 비콘 기반의 위치추정 센서
- 다수의 위성에 대한 통신 시간에 대한 차이를 (i.e. time delays)
이용하여 위성-로봇의 거리 값을 구하고, 삼각측량을 통해서
localization 수행
- GPS (US), GLONASS (Russia), BeiDou (China), Gallileo
(Europe) 등 각각의 나라/대륙에서 관리하는 시스템이 있음

• 장점
- GNSS는 전 세계적으로 사용할 수 있어 지리적 제약이 거의 없음
- 점점 더 저렴해지고 있으며 구하기 쉬움

• 단점
- Single GPS의 경우 부정확함 (5~20m 정도의 위치 오차)
- Cold Start 상태에서 위치 수렴까지 몇 초에서 몇 분이 걸릴 수 있음
- RTK-GPS, DGPS, A-GPS 등을 이용하면 오차가 cm 단위로 내려오면서 훨씬 정확해지나, 가격도 굉장히 높아짐
- 고층 건물, 숲, 터널, 실내 환경에서는 신호가 차단되거나 반사로 인해 정확도가 떨어짐 (multi-path 문제)
- 실내/지하에서는 신호를 아예 받을 수 없는 경우가 대부분임

### SLAM 관점에서 활용 – GNSS

• Outdoor Navigation
• INS (Inertial Navigation System)
- IMU의 관성 데이터를 바탕으로 연속적인 위치와 속도를 계산하고, GNSS에서 주기적으로 제공하는 위치 데이터를 이용해
IMU의 누적 오차를 보정

## LiDAR (Light Detection And Ranging)

• 적외선 레이저를 쏘아 반사되어 돌아오는 시간을 측량하여 거리를 잴 수 있는 센서
- 시간 측정을 위한 3가지 방식
    - Pulse를 이용한 Time-of-flight
    - Phase shift
    - Frequency modulation

• 3D point cloud 형태로 데이터를 받기 때문에, 주변환경의 3D 구조를 바로 알 수 있음
- Scanning LiDAR (Rolling shutter 방식과 유사함)
    - Mechanical Scanning (Macro-mechanical, Micro-motio, Prisms)
    - Solid State Scanning (MEMS, Electro-optical, Optical phased array)
- Flash LiDAR (Global shutter 방식과 유사함)

• 장점
- 센서가 추정한 3D 구조가 타 센서에 비해 훨씬 정확한 편
- 센서마다 다르지만, 자율주행용 LiDAR의 경우 ~100m 정도 거리까지 커버가 가능함
- 특정 적외선 파장을 사용하기 때문에 빛의 파장 간섭 등이 잘 일어나지 않음 (동일한 device를 여러 곳에서 사용하는 경우 제외)
- Reflectance (i.e. 쏜 레이저와 돌아온 레이저의 신호 세기를 비교하여 반사량을 계산 가능)
    - reflectance를 이용하여 자율주행에서는 차선이나 횡단보도 패턴을 읽을 수도 있음

• 단점
- 물론 가격은 지속적으로 낮아지고 있지만, 아직 카메라, RADAR, Ultrasonic 센서에 비해 비쌈
- Resolution의 한계: LiDAR 이미징 센서는 아직 카메라와 비교하였을 때 센서 resolution이 많이 부족함
- 눈이 오거나 비가 올 때 레이저가 눈/비에 막히기 때문에 작동하기 어려움
- Solid-state의 경우 360도 방향을 커버하기 위해 여러 개의 센서가 필요함


## RADAR (RAdio Detection And Ranging)
• 전파(radio wave)를 이용해서 주변 환경에 반사되어 돌아오는 전파를 측정하여 radial 거리를 재는 센서
- 돌아오는 전파의 각도 + 돌아오는데 걸리는 시간을 이용해서 주변 환경에 대한 거리를 추정
- Doppler 효과(물체가 움직일 때 발생하는 주파수 변화 현상)를 이용해서 물체의 속도를 측정 가능
- 전파의 종류를 바꿈으로써 near-range와 long-range를 정할 수 있음

• 장점
- 날씨의 영향을 잘 받지 않음
- 타 센서에서 얻지 못하는 ‘속도’ 값을 얻을 수 있음

• 단점
- 작은 물체들은 detection에 실패할 수 있음
- LiDAR보다 resolution이 낮음
- 주변에 벽이나 바닥에 대해 multipath 문제가 있을 수 있음


## Ultrasonic

• RADAR와 작동방식이 거의 동일하나, 초음파를 이용함

• 장점
- 저렴함
- Near-range에서 잘 작동함 (긴급 제동)

• 단점
- Geometry를 잘 추정하는 편은 아님
- 다중 센서를 이용해서 geometry 추정을 할 수는 있지만 좋은 편은 아님
- 노이즈가 많음

## Camera

• 카메라는 렌즈를 통해 수집한 빛을 이미지 센서에 전달하고, 이미지 센서는 빛의 강도와 색상 정보를 전기 신호로 변환. 이후, 색상 필터
패턴 (예: Bayer 필터)을 사용하여 각 픽셀의 색상 정보를 분리하고, 이를 재구성하여 최종 컬러 이미지를 형성(=debayering)

• 필터를 사용하지 않으면 Monochrome 카메라, 또는 RGB가 아닌 다른 특정 파장으로 특수 카메라 (e.g. 열화상 카메라, 적외선
카메라)를 만들 수 있음

• 장점
- 사람이 보는 시야와 가장 유사한 데이터를 뽑음
- 저렴한 센서임에도 texture가 충만한 dense한 정보를 가짐
- FPS가 높은 편 (30fps, 60fps)
- 렌즈를 바꿈으로써 시야각을 바꿀 수 있음 (광각 카메라)

• 단점
- Monocular Camera의 경우 Depth 정보가 없음
(Stereovision을 통해 Depth를 구현할 수 있지만, 계산량이 적지 않음)
- 조명에 대한 영향을 많이 받음
    - 어두운 곳에서는 좋은 데이터가 많이 안들어옴
    - 너무 밝거나 빛반사가 카메라에 바로 오는 경우 작동하지 않을 수 있음
- Motion Bulr
