# Nav2에 사용되는 ROS 2 개념
## Action Server
• 네비게이션(Navigation)과 같이 긴 작업을 수행하는 로봇 동작을
제어하는 핵심 개념

• 장시간 작업 상황에서 액션 서버는 클라이언트로부터 다른
프로세스나 스레드에서 장기간 실행되는 작업 요청을 수락하고
실행이 완료되면 최종 결과를 반환하며 해당 상태를 종료

• 작업이 완료될때까지 안정성을 위해 액션 서버는 클라이언트에게
feedback을 제공 (목표 지점까지의 각도, 성공 여부 등)

• 실제로 다양한 기능 및 동작들이 Action으로 구현되어 있음
https://github.com/ros-navigation/navigation2/tree/main/nav2_msgs/action

## Lifecycle Node
• ROS 2에서 노드(Node)의 상태를 관리하기 위해 사용되는 개념
- 노드의 초기화, 활성화, 일시 중지, 종료 등과 같은 다양한 상태를 체계적으로 관리
- 만약 서버가 충돌하는 경우 lifecycle manager에게 이를 알리고 시스템을 다운시켜 심각한 문제를 방지

• configure(노드를 생성할 때 필요한 상태), activate(노드가 실행될 때 필요한 상태), deactive(노드가 중지 될 때 필요한 상태) 등과 같은 노드의 상태를 Lifecycle이 관리
![](/assets/img/Screenshot%20from%202025-12-18%2009-33-58.png)
• 정의된 lifecycle 상태에 따라 적절한 동작을 수행할 수 있도록 설계되며, 로봇 및 시스템의 제어 및 운영을 효율적으로 관리할 수 있게 해줌

• 모든 ROS 시스템은 가능하면 이 lifecycle 노드를 사용하는 것이 권장되며 Nav2는 모든 서버에서 lifecycle node framework을 활용할 만큼 광범위하게 사용되고 있음

![](/assets/img/Screenshot%20from%202025-12-18%2009-34-46.png)


# Nav2를 구성하는 핵심 요소
## Behavior Tree (행동 트리)
![](/assets/img/Screenshot%20from%202025-12-18%2009-36-34.png)

• Tree 구조로 여러 Node들이 나무 가지처럼 연결된 계층적 자료 구조

• 트리의 왼쪽부터 오른쪽으로 탐색하며 서로 의존성이 없는 노드들이 실행되는 형태

• Nav2에서는 Behavior Tree library로 [BehaviorTree CPP](https://www.behaviortree.dev/)를 사용

![](/assets/img/Screenshot%20from%202025-12-18%2009-36-45.png)

## Navigation Servers
![](/assets/img/Screenshot%20from%202025-12-18%2009-41-30.png)

• Planner Server
- ROS의 Global Planner와 동일
- 지도의 알려진 장애물 및 벽 정보를 바탕으로 로봇이 A 지점에서 B 지점까지 이동하는 경로를 찾음

• Controller Server
- ROS의 Local Planner와 동일
- 현재 위치에서 몇 미터 전방까지(센서 범위까지) 반응형 경로 계획을 수행

![](/assets/img/Screenshot%20from%202025-12-18%2009-42-39.png)

• Smoother Server
- 로봇의 경로를 보다 부드럽게 만드는 데 사용
- 주로 로봇이 목표 지점으로 이동할 때 경로의 급격한 회전이나 불규칙한 움직임을 최소화하여 더욱 자연스럽고 효율적으로 움직이게 하는 역할

• Behavior Server
- 특정 상황이나 요구 사항에 따라 로봇의 동작(Behavior)을 제어하고 관리
- 다양한 복구 동작과 일반적인 행동을 보다 일관되고 통합된 방식으로 관리하기 위해, 기존 Recovery라는 용어가 Behavior로 통합

## Environmental Representation (환경 표현)
![](/assets/img/Screenshot%20from%202025-12-18%2009-44-35.png)

• Costmap
- 로봇이 이동할 수 있는 영역과 이동할 수 없는 영역을 나타내는 2차원 그리드 맵
- 각 셀은 특정 비용(Cost) 값을 가지며, 이 비용 값은 로봇이 해당 셀을 통과하는 데 얼마나 어려운지를 나타냄

• Layer
- 코스트맵에 특정 기능을 추가하는 역할 (예를 들어, 장애물을 추적하거나 안전하지 않은 영역을 표시)

• Costmap Filter
- 코스트맵 유형에 따라 로봇의 행동을 변경할 수 있게 해줌 (예를 들어, 특정 지역을 피하거나 속도를 제한하는 등의 기능을 수행)
