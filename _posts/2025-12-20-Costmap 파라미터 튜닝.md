# Costmap 2D 파라미터 튜닝

---

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      update_frequency: 1.0
      publish_frequency: 1.0
      global_frame: map
      robot_base_frame: base_footprint
      use_sim_time: False
      robot_radius: 0.20
      resolution: 0.05
      track_unknown_space: true
      plugins: ["static_layer", "obstacle_layer", "inflation_layer"]

      ...

local_costmap:
  local_costmap:
    ros__parameters:
      update_frequency: 5.0
      publish_frequency: 2.0
      global_frame: odom
      robot_base_frame: base_footprint
      use_sim_time: False
      rolling_window: true
      width: 3
      height: 3
      resolution: 0.05
      robot_radius: 0.20
      plugins: ["voxel_layer", "inflation_layer"]
      
      ...
```

- **`update_frequency`** (double, 기본값: 5.0)
    - Costmap을 업데이트하는 빈도 (Hz)
    - global_costmap인 경우
        - 실시간 반응이 중요한 경우 높은 값을 사용하고, 그렇지 않다면 낮은 값(예: 1.0 Hz)으로 설정해도 무방
    - local_costmap인 경우
        - 주로 높은 빈도(예: 5.0 Hz)로 설정해 최신 상태의 맵을 유지하지만 CPU 사용량이 증가할 수 있음
- **`publish_frequency`** (double, 기본값: 1.0)
    - Costmap을 퍼블리시하는 빈도 (Hz, 0.0: 비활성화)
    - RViz와 같은 시각화 도구에서 맵을 모니터링할 때 유용
    - 시각화가 필요하지 않은 경우 낮은 빈도로 설정하여 시스템 자원을 절약할 수 있음
- **`global_frame`** (string, 기본값: "map")
    - Costmap이 작동할 전역 프레임
    - **global_costmap**인 경우 ⇒ "map" 추천 (전역 좌표계 사용을 위해)
        - SLAM이나 AMCL과 같은 위치 추정 시스템을 사용하여 지속적으로 업데이트하여 로봇의 전역 위치를 사용해야 하는 경우
        - 로봇이 큰 환경에서 장거리 이동을 할 때 전역 위치의 정확성을 유지
        - 로봇의 경로 계획이 전체 환경을 포괄해야 하는 경우에 적합
    - **local_costmap**인 경우 ⇒ "odom" 추천 (지역 좌표계 사용을 위해)
        - 로봇이 빠르게 이동하고, 실시간으로 주변 환경의 변화를 반영해야 하는 경우
        - 로봇이 주로 작은 영역 내에서 이동하고, 장거리 이동이 필요 없는 경우
        - 복잡한 실내 환경에서 로봇이 자주 방향을 바꾸고, 많은 장애물을 피해야 하는 경우
- **`robot_base_frame`** (string, 기본값: "base_link")
    - 로봇의 기본 링크 프레임
- **`transform_tolerance`** (double, 기본값: 0.3)
    - tf 데이터의 지연을 허용하는 시간(초)
- **`width`, `height`** (double, 기본값: 5.0)
    - Costmap의 가로과 세로 (m)
    - **global_costmap**의 경우
        - static_layer을 사용할 경우, 신경쓰지 않아도 됨
        - 동적인 환경의 경우 충분히 넓게 설정해야 함
    - **local_costmap**의 경우 로봇 주변의 적절한 영역을 커버하도록 설정
    ![](/assets/img/Peek%202025-12-20%2012-51.gif)
- **`resolution`** (double, 기본값: 0.1)
    - Costmap의 해상도(미터당 셀 크기)
    - 고해상도(예: 0.05m)는 더 정밀한 맵을 제공하지만 메모리 사용량이 증가
- **`rolling_window`** (bool, 기본값: false)
    - 로봇 주변의 환경을 지속적으로 업데이트하는데 사용되는 기능
    - **true** 설정 시, costmap은 로봇이 움직일 때마다 업데이트되며, 로봇을 중심으로 한 일정한 영역 내의 장애물 정보를 유지
    - **global_costmap**인 경우 ⇒ "false" 추천
        - 전체 환경을 한 번에 파악하여 장기 경로 계획을 수립해야 하기 때문
    - **local_costmap**인 경우 ⇒ "true" 추천
        - 로봇이 새로운 위치에 도달했을 때 주변의 장애물 정보를 계속 갱신해야하기 때문
    ![](/assets/img/Peek%202025-12-20%2012-54.gif)
- **footprint 관련 파라미터**
    - **`robot_radius`** (double, 기본값: 0.1)        
        - 로봇의 물리적인 바닥 면적을 정의 (원형 로봇의 반경을 정의)
    - **`footprint`** (double, 기본값: 0.1)
        - 로봇의 물리적인 바닥 면적을 정의 (원형 로봇이 아닌 경우 정의)
        - 예) footprint: [[x1, y1], [x2, y2], [x3, y3], [x4, y4]]
    - **`footprint_padding`** (double, 기본값: 0.1)
        - 로봇의 footprint 주위에 추가되는 여유 공간(패딩)을 설정
        - 너무 큰 값은 로봇의 이동을 제한할 수 있음
        - **robot_radius**, **footprint**에 모두 영향을 줌

- **`plugins`** (vector<string>, 기본값: [“static_layer”, “obstacle_layer”, “inflation_layer”])
    
    [costmap plugins 튜닝](#costmap-plugins-튜닝)
    
    | Namespace | Plugin | Description |
    | --- | --- | --- |
    | “static_layer” | “nav2_costmap_2d::StaticLayer” | 사전에 정의된 맵 파일을 로드하여 환경의 고정된 장애물 정보를 costmap에 반영 |
    | “obstacle_layer” | “nav2_costmap_2d::ObstacleLayer” | 로봇의 센서를 사용하여 동적인 장애물을 감지하고 costmap에 반영 |
    | “inflation_layer” | “nav2_costmap_2d::InflationLayer” | 장애물 주변에 안전 영역을 설정하여, 로봇이 장애물과 안전 거리를 유지 |
    | “voxel_layer” | “nav2_costmap_2d::VoxelLayer” | 3차원 공간에서 장애물을 표현하기 위해 사용 |

# costmap plugins 튜닝

# [Static Layer](https://docs.nav2.org/configuration/packages/costmap-plugins/static.html)

- 사전에 정의된 맵 파일을 로드하여 환경의 고정된 장애물 정보를 costmap에 반영
- 로봇이 작업하는 동안 변하지 않는 장애물(예: 벽, 고정된 가구 등)을 나타냄

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
    
			...
			
      plugins: ["**static_layer**", "obstacle_layer", "inflation_layer"]

			...
			
      static_layer:
        plugin: "nav2_costmap_2d::StaticLayer"
        map_subscribe_transient_local: True

			...
```

- **`subscribe_to_updates`** (bool, 기본값: false)
    - 맵 서버에서 업데이트된 맵을 수신할지 여부를 결정
    - 환경이 정적이라면 false로 설정 / 환경이 동적이고 맵이 자주 업데이트된다면 true로 설정

# [Obstacle Layer](https://docs.nav2.org/configuration/packages/costmap-plugins/obstacle.html)

- 레이저 스캐너, 초음파 센서 등에서 데이터를 받아 동적인 장애물을 감지
- 감지된 장애물을 costmap에 반영하여, 로봇이 회피 경로를 계획할 수 있도록 도움

```yaml
global_costmap:
  global_costmap:
    ros__parameters:

			...

      plugins: ["static_layer", "obstacle_layer", "inflation_layer"]
      obstacle_layer:
        plugin: "nav2_costmap_2d::ObstacleLayer"
        enabled: True
        observation_sources: scan
        scan:
          topic: /scan
          max_obstacle_height: 2.0
          clearing: True
          marking: True
          data_type: "LaserScan"
          raytrace_max_range: 10.0
          raytrace_min_range: 0.0
          obstacle_max_range: 2.5
          obstacle_min_range: 0.0

			...
```

- **`observation_sources`** (vector\<string>, 기본값: [””])
    - 장애물을 감지할 센서 소스를 정의
    - 멀티 센서를 사용할 경우 아래와 같이 설정
        
        ```yaml
        ...
        
        obstacle_layer:
          enabled: true
          observation_sources: **laser_scan_sensor** **point_cloud_sensor**
        
          **laser_scan_sensor**:
            sensor_frame: "base_scan"
            data_type: "LaserScan"
            topic: /scan
            ...
        
          **point_cloud_sensor**:
            sensor_frame: "camera_link"
            data_type: "PointCloud2"
            topic: /camera/depth/points
            ...
        ```
        
- **sensor source parameters**
    - **`max_obstacle_height`** (double, 기본값: 2.0)
        - 장애물로 인식될 최대 높이를 지정 (이 값보다 높은 장애물은 무시)
        - 로봇이 넘어다닐 수 있는 장애물의 높이를 고려하여 설정
    - **`clearing`** (bool, 기본값: false)
        - 로봇의 센서가 특정 구역에서 장애물을 제거하는 데 사용
        - 로봇이 이동할 때 환경을 신속하게 업데이트해야 하는 경우에 설정
    - **`marking`** (bool, 기본값: true)
        - 로봇의 센서가 장애물을 표시하는 데 사용
        - 로봇이 이동하면서 감지한 장애물을 맵에 추가
        - 일반적으로 이 값을 활성화하여 로봇이 장애물을 지속적으로 업데이트
    - **`raytrace_max_range`** (double, 기본값: 3.0)
        - 레이 트레이싱(Ray Tracing)을 통해 장애물을 감지할 때의 최대 거리를 지정
            
            ⇒ Ray Tracing: 센서 데이터를 이용하여 로봇의 주변 환경을 감지하고 장애물을 탐지
            
        - 너무 크게 설정하면 불필요한 장애물 정보를 가져올 수 있으므로, 센서의 실제 유효 범위에 맞게 설정
        - 로봇의 컴퓨팅 성능과 실시간 데이터 처리 능력을 고려하여 설정 필요
    - **`raytrace_min_range`** (double, 기본값: 0.0)
        - 레이 트레이싱을 통해 장애물을 감지할 때의 최소 거리를 지정
        - 너무 작게 설정하면 노이즈가 발생할 수 있으므로, 로봇의 센서 특성에 맞게 설정
    - **`obstacle_max_range`** (double, 기본값: 2.5)
        - 장애물로 인식될 최대 거리를 지정 (이 값보다 먼 거리에 있는 장애물은 무시)
        - 로봇이 실제로 회피할 필요가 있는 범위를 커버할 수 있도록 지정
    - **`obstacle_min_range`** (double, 기본값: 2.0)
        - 장애물로 인식될 최소 거리를 지정 (이 값보다 가까운 거리에 있는 장애물은 무시)
        - 로봇이 실제로 회피할 필요가 있는 범위를 커버할 수 있도록 지정

# [Inflation Layer](https://docs.nav2.org/configuration/packages/costmap-plugins/inflation.html)

- 장애물 주위에 일정한 거리만큼의 안전 영역을 설정
- 로봇이 장애물에 너무 가깝게 접근하지 않도록 방지

![Low Inflation](/assets/img/low%20inflation.png)

Low Inflation

![High Inflation](/assets/img/high%20inflation.png)

High Inflation

```yaml
local_costmap:
  local_costmap:
    ros__parameters:

			...

      plugins: ["voxel_layer", "inflation_layer"]
      inflation_layer:
        plugin: "nav2_costmap_2d::InflationLayer"
        cost_scaling_factor: 3.0
        inflation_radius: 0.55

			...
```

- **inflation_radius** (double, 기본값: 0.55)
    - 장애물 주변에 인플레이션을 적용할 반경을 지정
    - 인플레이션 반경 내의 셀들은 장애물에 가까울수록 높은 비용을 갖게 되어 로봇이 해당 영역을 피함
    - 큰 로봇일수록 더 넓은 인플레이션 반경이 필요할 수 있음
    - 너무 작게 설정하면 장애물에 근접할 위험이 있고, 너무 크게 설정하면 경로 계획이 비효율적일 수 있음
- **cost_scaling_factor** (double, 기본값: 10.0)
    - 인플레이션 cost를 증가시키는 비율
    - 장애물에 가까울수록 비용이 기하급수적으로 증가하게 되며, 이 비율은 그 증가율을 결정
    - 높은 값을 설정하면 장애물 주변이 매우 높은 비용을 가지므로 로봇이 장애물에서 멀리 떨어진 경로를 선택 (낮을 경우 장애물 근처를 통과하는 경로도 가능)
- **inflate_unknown** (bool, 기본값: false)
    - 알려지지 않은 영역에서 인플레이션할지 여부를 결정
    - 설정되면, 알려지지 않은 영역도 장애물처럼 취급되어 인플레이션이 적용
    - 탐색되지 않은 영역이 위험할 가능성이 있다면, 이 값을 true로 설정하여 안전성을 높임
    - 탐색되지 않은 영역을 무시해도 괜찮다면, false로 설정하여 경로 계획의 유연성을 높임
- **inflate_around_unknown** (bool, 기본값: false)
    - 로봇이 알려지지 않은 영역 근처를 피하도록 하기 위해 이 값을 사용

# [Voxel Layer](https://docs.nav2.org/configuration/packages/costmap-plugins/voxel.html)

- 3D 센서(예: 3D LiDAR, Depth Sensor)에서 데이터를 받아서 장애물을 3D 그리드 형태로 표현
- 높이 정보가 있는 장애물을 감지하고 반영하여, 더 정확한 장애물 회피 경로를 계획할 수 있도록 도움

```yaml
local_costmap:
  local_costmap:
    ros__parameters:

			...

      plugins: ["voxel_layer", "inflation_layer"]

			...

      voxel_layer:
        plugin: "nav2_costmap_2d::VoxelLayer"
        enabled: True
        publish_voxel_map: True
        origin_z: 0.0
        z_resolution: 0.05
        z_voxels: 16
        max_obstacle_height: 2.0
        mark_threshold: 0
        observation_sources: scan
        scan:
          topic: /scan
          max_obstacle_height: 2.0
          clearing: True
          marking: True
          data_type: "LaserScan"
          raytrace_max_range: 10.0
          raytrace_min_range: 0.0
          obstacle_max_range: 2.5
          obstacle_min_range: 0.0
```

- **publish_voxel_map** (bool, 기본값: false)
    - 현재 생성된 3D 보셀 맵을 주기적으로 publish할지 여부를 결정 (디버깅이나 시각화용)
- **origin_z** (double, 기본값: 0.0)
    - **설명**: voxel 그리드의 z축 원점을 설정 (voxel 맵이 시작되는 z축의 위치를 정의)
    - 로봇이 주행하는 환경의 높이를 고려하여 설정 (예를 들어, 로봇이 지면에서부터 높이를 인식해야 한다면 지면 높이로 설정)
- **z_resolution** (double, 기본값: 0.2)
    - voxel 그리드의 z축 해상도를 설정 (z축 방향에서 각 voxel의 높이를 결정)
    - 높은 해상도는 더 정확한 맵을 제공하지만, 연산량이 증가할 수 있음
    - 일반적으로 로봇이 주행하는 환경에서 필요한 최소 해상도로 설정
- **z_voxels** (int, 기본값: 10)
    - z축 방향에서 voxel 그리드의 voxel 수를 설정 (맵의 z축 범위를 결정)
    - 로봇이 인식해야 하는 최대 높이를 기준으로 설정
    - 로봇이 낮은 천장 아래에서 작업해야 하는 경우, 해당 높이를 충분히 커버할 수 있도록 설정
- **max_obstacle_height** (double, 기본값: 0.0)
    - 장애물로 인식할 최대 높이를 설정 (이 값보다 높은 객체는 장애물로 인식되지 않음)
    - 로봇이 주행하는 환경에서 가장 높은 장애물의 높이를 고려하여 설정
    - 로봇이 주행 가능한 모든 높이를 포함하도록 설정
- **sensor source parameters**
    - 위 [Obstacle Layer 부분](#obstacle-layer) 참고 (내용 동일)
