# IMU의 가속도 및 각속도 보정

---

>   로봇 오도메트리 정보를 보았을 때 이동 중 상당한 편차가 관찰되는 경우, 아래 과정들을 통해 보정할 수 있습니다.    
>

> 보정은 이러한 편차를 최소화하는 것을 목표로 하지만, 센서 특성 상 실제 하드웨어 편차는 없을 수가 없음. 따라서 요구 사항에 합리적으로 맞는 수준으로 보정
> 

## 가속도계와 자이로스코프의 바이어스를 추정하고 보정

- IMU의 바이어스는 IMU 센서가 측정하는 값과 실제 측정되어야 하는 값 사이에 일정하게 존재하는 오프셋(offset)입니다.
    - 쉽게 말해, IMU 센서가 0이어야 할 때도 어느 정도 일정한 값이 출력되는 현상

1. VNC Viewer 또는 VS Code 환경을 통해 Docker ROS 2 터미널을 열어줍니다.
2. 아래 명령을 실행하여 ROS 관련 서비스를 모두 비활성화합니다.
    
    ```bash
    ~/.stop_ros.sh
    ```
    
3. MCU에서 IMU 정보 수신 및 publish를 포함한 기능만 사용하기 위해 아래 런치파일을 실행시킵니다.
    
    ```bash
    ros2 launch ros_robot_controller ros_robot_controller.launch.py
    ```
    
4. 새 ROS2 터미널을 열고 다음 명령을 입력한 후 Enter 키를 눌러 IMU 보정을 시작합니다.
    
    ```bash
    ros2 run imu_calib do_calib --ros-args -r imu:=/ros_robot_controller/imu_raw --param output_file:=/home/ubuntu/ros2_ws/src/calibration/config/imu_calib.yaml
    ```
![](/assets/img/HiWonderPi/img/Screenshot%20from%202025-12-23%2016-21-03.png)


7. 보정 후 명령을 실행하여 보정된 결과를 시각화를 통해 확인합니다.
    
    ```bash
    ros2 launch peripherals imu_view.launch.py
    ```
![](/assets/img/HiWonderPi/img/IMG_4418.JPG)
![](/assets/img/HiWonderPi/img/IMG_4419.JPG)
![](/assets/img/HiWonderPi/img/IMG_4421.JPG)
![](/assets/img/HiWonderPi/img/IMG_4422.JPG)


8. 모든 터미널을 종료하고, 도커 밖 LXTerminal에서 아래 명령어로 ROS 관련된 서비스를 재시작 합니다. 부저가 울린다면 정상적으로 완료된 것 입니다.
    
    ```bash
    sudo systemctl restart start_node.service
    ```

## 각속도 스케일 보정

> Ackermann 버전의 MentorPi는 각속도 보정이 필요하지 않습니다.
> 
1. VNC Viewer에서 Docker ROS 2 터미널을 열어줍니다.
2. 아래 명령을 실행하여 ROS 관련 서비스를 모두 비활성화합니다.
```bash
~/.stop_ros.sh
```

3. `~/ros2_ws/src/driver/controller/config` 경로의 `calibrate_params.yaml` 파일을 열어주고, 각속도 매개변수를 1.0으로 수정한 다음 보정을 진행합니다.
    
    ![](https://docs.hiwonder.com/projects/MentorPi/en/latest/_static/media/4.MotionControlLesson/4.3/media/image24.png)
    
4. 아래 명령을 입력하고 Enter를 눌러 각속도 보정을 시작합니다.
    
    ```bash
    ros2 launch calibration angular_calib.launch.py
    ```
    ![](/assets/img/HiWonderPi/img/Screenshot%20from%202025-12-23%2016-32-51.png)
    - `test_angle`: 테스트 회전 각도를 지정하며, 기본값은 360°
    - `speed`: 각속도
    - `tolerance`: 허용 오차 범위
    - `odom_angle_scale_correction`: Odometry 각도 측정의 스케일 보정
    - `start_test`: Odometry 각도 스케일 보정 테스트를 시작하는 버튼
6. `start_test` 옵션을 체크하면 로봇이 제자리에서 회전합니다. 회전량이 360°와 다르다면 못하면 `odom_angule_scale_correction` 값을 조정해야 합니다. 이 값은 모터의 회전 스케일을 제어합니다. 이 값을 0.01씩 조정하는 것이 권장됩니다.

7. 보정 후 다시 `~/ros2_ws/src/driver/controller/config` 경로의 `calibrate_params.yaml` 파일을 열어주고, `angular_correctqion_factor`의 값을 “**odom_angule_scale_correction**”의 조정된 값으로 수정합니다.
    
    ![](https://docs.hiwonder.com/projects/MentorPi/en/latest/_static/media/4.MotionControlLesson/4.3/media/image29.png)
    
8. 모든 터미널을 종료하고, 도커 밖 LXTerminal에서 아래 명령어로 ROS 관련된 서비스를 재시작 합니다. 부저가 울린다면 정상적으로 완료된 것 입니다.
    
    ```bash
    sudo systemctl restart start_node.service
    ```


## 선속도 스케일 보정

> Ackermann 버전의 MentorPi는 선속도 보정이 필요하지 않습니다.
> 
1. 로봇을 평평하고 개방된 표면에 배치하고, VNC Viewer에서 Docker ROS 2 터미널을 열어줍니다.
2. 아래 명령을 실행하여 ROS 관련 서비스를 모두 비활성화합니다.
    
    ```bash
    ~/.stop_ros.sh
    ```
    
3. `~/ros2_ws/src/driver/controller/config` 경로의 `calibrate_params.yaml` 파일을 열어주고, 선속도 매개변수 `linear_correction_factor`를 1.0으로 수정한 다음 보정을 진행합니다.
    
    ![](https://docs.hiwonder.com/projects/MentorPi/en/latest/_static/media/4.MotionControlLesson/4.3/media/image30.png)
    
4. 아래 명령을 입력하고 Enter를 눌러 선속도 보정을 시작합니다.
    
    ```bash
    ros2 launch calibration linear_calib.launch.py
    ```
    
5. 왼쪽의 `calibrate_linear`를 클릭합니다. 보정 인터페이스가 아래와 같이 나타납니다.
![](/assets/img/HiWonderPi/img/Screenshot%20from%202025-12-23%2016-43-53.png)

- `test_angle`: 테스트 이동 거리를 지정하며, 기본값은 1m
- `speed`: 선속도
- `tolerance`: 허용 오차 범위
- `odom_angle_scale_correction`: Odometry 이동량 측정의 스케일 보정
- `start_test`: Odometry 이동 스케일 보정 테스트를 시작하는 버튼
6. 로봇이 제대로 정렬되고 시작점 표시에 배치되었는지 확인합니다. `start_test` 확인란을 선택하면 로봇이 앞으로 이동합니다. 로봇이 직선으로 이동하는지 관찰합니다. 편차가 있으면 `odom_linear_scale_correction` 값을 조정합니다. 이 값은 전진 이동에 대한 모터의 스케일링 팩터를 조정합니다. 이 값을 매번 0.01씩 조정하는 것이 권장됩니다.

7. 보정 후 다시 `~/ros2_ws/src/driver/controller/config` 경로의 `calibrate_params.yaml` 파일을 열어주고, `linear_correction_factor`의 값을 “**odom_linear_scale_correction**”의 조정된 값으로 수정합니다.
    
    ![](https://docs.hiwonder.com/projects/MentorPi/en/latest/_static/media/4.MotionControlLesson/4.3/media/image30.png)
    
8. 모든 터미널을 종료하고, 도커 밖 LXTerminal에서 아래 명령어로 ROS 관련된 서비스를 재시작 합니다. 부저가 울린다면 정상적으로 완료된 것 입니다.
    
    ```bash
    sudo systemctl restart start_node.service
    ```

    
## Scale Calibration 정리

### **calibrate_angular.py - 각도 회전 보정**

- **목적**: Wheel encoder 기반 odometry의 회전 각도 보정
- **작동 방식**
    1. TF에서 `odom → base_footprint` 변환을 읽어 현재 yaw 각도 확인
    2. `test_angle`만큼 회전하도록 로봇 제어
    3. 실제 회전 각도 계산
    4. 보정 계수(`odom_angular_scale_correction`)로 실제 각도와의 차이 보정

### **calibrate_linear.py - 선형 이동 거리 보정**

- **목적**: Wheel encoder 기반 odometry의 선형 이동 거리 보정
- **작동 방식**
    1. TF에서 `odom → base_footprint` 변환을 읽어 실제 위치를 확인
    2. 시작 위치 저장
    3. `test_distance`만큼 이동하도록 로봇 제어
    4. 실제 이동 거리 계산
    5. 보정 계수(`odom_linear_scale_correction`)로 실제 거리와의 차이 보정

### **계산한 scale 정보는 어디서 사용될까요?**

- 이 보정 계수들은 **`odom_publisher_node.py`**에서 사용됩니다.
    - `linear_correction_factor`: 선형 보정 계수
    - `angular_correction_factor`: 각도 보정 계수
    
    ```python
    ...
    self.odom.pose.pose.position.x = **self.linear_factor** * self.x
    self.odom.pose.pose.position.y = **self.linear_factor** * self.y
    ...
    ```
